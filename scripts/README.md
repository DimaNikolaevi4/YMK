# 📜 Справочник скриптов YMK

Эта папка содержит все инструменты для автоматизации работы с КТП (календарно-тематическими планами), РП (рабочими программами) и Перечнями. Все скрипты написаны на Python 3 и используют `python-docx` + `openpyxl`.

## 🗺️ Структура папки

```
scripts/
├── README.md            # этот файл — карта скриптов
├── *.py (43 файла)      # основные скрипты
├── *.json (13 файлов)   # данные для генерации КТП
├── _archive/            # устаревшие одноразовые скрипты (см. _archive/README.md)
└── _utils/              # утилиты поиска литературы (см. _utils/README.md)
```

## 🚀 Основные точки входа

Эти скрипты запускаются напрямую для выполнения основных задач:

| Скрипт | Назначение |
|---|---|
| `generate_ktp_docx.py` | **Главный генератор КТП** — собирает `.docx` из JSON-данных по эталону `KTP/КТП МДК 05.02 М 2 курс.docx`. Канонический инструмент. |
| `generate_ktp_clean.py` | Альтернативная версия генератора с минимальным XML-подходом (cell margins через OxmlElement). |
| `generate_ktp_05_02.py` | Специализированный генератор КТП МДК 05.02 для семестров 3+4 (группа М-21). |
| `validate_ktp.py` | **Основной валидатор** — 29 проверок: суммы часов, структура таблиц, шрифты, свежесть литературы. |
| `validate_final.py` | Финальная проверка перед утверждением (gridSpan через XML, не python-docx proxies). |
| `parse_rp.py` | **Парсер РП** — извлекает МДК, темы, часы, компетенции из РП в JSON. |

## 📄 Перечни материалов

| Файл | Назначение |
|---|---|
| `generate_perechen_docx.py` | **Генератор перечня** — собирает `.docx` из JSON по блокам: `title`, `control`, `requirements`, `works`, `course_project`, `questions`, `criteria`, `student_lists`. |
| `import_perechen_etalon.py` | Разбор образца `.docx` в JSON (раскладка по блокам схемы). Использован для `data_perechen_sample_pm02.json`. |
| `data_perechen_mdk0201_kip31.json` | Данные перечня МДК 02.01 (КИП-31): 15.01.31, диф. зачёт, 2026-2027 — 4 темы с практическими занятиями, 26 вопросов. |
| `data_perechen_sample_pm02.json` | Данные образца `Перечни/02_Архивные/перечень ПМ 02 МДК 02.01.docx` — сверка и regression. |
| `data_perechen_kdz_pm02.json` | Перечень КДЗ ПМ.02 (С-21, С-22): МДК 02.01 + 02.02, 19 практических занятий, вопросы двумя частями — 36 + 36, занятие 24. |
| `data_perechen_pa02_exam.json` | Перечень ПА.02 (С-21, С-22): экзамен по модулю, 30 билетов (теория из банка вопросов + практическое задание). |

Запуск из корня репозитория:

```bash
python scripts/generate_perechen_docx.py \
  --data scripts/data_perechen_mdk0201_kip31.json \
  --out "Перечни/01_Готовые/перечень МДК 02.01 КИП-31.docx" \
  --blocks all
```

Отдельные блоки: `--blocks title,control` соберёт только титул и таблицу «Контроль знаний»;
`--blocks questions,criteria` — только вопросы и критерии (удобно для проверки на данных другого МДК).

Требуется `python-docx`.

**Статус на 2026-10-26:** реализованы все 8 блоков; перечень собран по реальным данным —
КИП-31, МДК 02.01 «Технология пуско-наладочных работ», дифференцированный зачёт, 2026-2027:
4 темы с практическими занятиями (1.1, 1.3, 1.5, 1.6; 22 занятия, нумерация как в КТП),
темы без работ не печатаются, самостоятельных и лабораторных нет — заголовок
«Перечень практических работ» и два столбца; 26 вопросов к диф. зачёту по ключевым
занятиям тем 1.1–1.8; лист ознакомления на 25 пустых строк. Блок `course_project`
в этот эталон не входит: курсового по МДК 02.01 нет.
Проверка: `validate_perechen.py` — 21 проверка, все пройдены.
Собраны три документа: МДК 02.01 КИП-31 (диф. зачёт), КДЗ ПМ.02 и ПА.02 ПМ.02 (С-21, С-22).
Вопросы можно задавать группами по МДК (`exam_questions.groups`) или билетами
(`exam_questions.kind = "tickets"`, список `tickets` с шапкой, вопросами и подписью).
Для документов уровня ПМ валидатор запускается с флагом `--all-mdk`.

**Правило:** названия ПМ и профессии берутся буква в букву из РП соответствующего ПМ
(`RP/02_Оригиналы/…`), а не из учебного плана — там профессия может называться иначе.
Критерии оценки: `"criteria": "short"` (вариант ПМ 02) или `"criteria": "extended"`
(вариант МДК 03.01/05.01/05.02), либо готовый объект `{"title": …, "items": […]}`.

## ⚙️ Типовой рабочий процесс (Workflow)

### Сценарий А: создание КТП «с нуля» по РП

```
1. Положить РП в RP/01_Актуальные/
2. dump_rp_*.py          → дамп таблиц РП (отладка)
3. extract_rp_data.py    → универсальный экстрактор РП в JSON
4. build_ktp_json.py     → сборка data-JSON для генератора
5. generate_ktp_docx.py  → генерация .docx КТП
6. validate_ktp.py       → 29 проверок (часы, структура, шрифты)
7. verify_ktp_vs_rp.py   → финальная сверка Т2 КТП vs РП 3.2
8. fill_pages_*.py      → заполнение кол.9 Т2 реальными страницами
9. validate_final.py     → финальная проверка перед утверждением
```

### Сценарий Б: синхронизация существующего КТП с новым РП

```
1. check_0201_0202_vs_rp.py     → сверка текущего КТП vs нового РП
2. sync_ktp_0201_0202_new_rp.py → синхронизация КТП с новым РП
3. sync_data_json_col8_col9.py  → синхронизация JSON с .docx (col.8/col.9)
4. validate_ktp.py              → 29 проверок
5. verify_ktp_vs_rp.py          → финальная сверка
```

## 📝 Примечания

- **Зависимости:** `python-docx`, `openpyxl`, `lxml`. Установить через `pip install -r requirements.txt` (если есть) или вручную.
- **Абсолютные пути:** многие скрипты содержат хардкоды `/home/z/my-project/YMK/...` — это путь в окружении ИИ-агента. На локальной машине заменить на путь к вашему клону репозитория.
- **Запуск:** все скрипты запускать из корня репозитория `YMK/`, а не из `scripts/`.
- **Обновление путей:** после миграции файлов (RP/→01_Актуальные/, Сверка→Сверки/) хардкоды в 13 скриптах обновлены 2026-10-23. См. коммиты `93c9ede`, `443ad01`, `5a13d48`.
