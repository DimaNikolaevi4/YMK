## 🎯 О проекте

Репозиторий изначально создавался для автоматической генерации **календарно-тематических планов (КТП)** по МДК на основе рабочих программ (РП). В ходе работы выяснилось, что накопленная методическая база (эталоны оформления, валидаторы, скрипты, форматы данных) одинаково применима и к другим типам методических документов, которые преподаватель СИТ готовит к промежуточной и итоговой аттестации.

Поэтому сфера репозитория **расширена** и теперь покрывает два параллельных направления:

| Направление | Документ | Эталон | Инструкции | Скрипты |
|---|---|---|---|---|
| **КТП** | Календарно-тематический план по МДК | `KTP/КТП МДК 05.02 М 2 курс.docx` | [`создание_КТП.md`](создание_КТП.md), [`KTP_INSTRUCTIONS.md`](KTP_INSTRUCTIONS.md), [`logic.md`](logic.md) | `scripts/generate_ktp_docx.py`, `scripts/validate_ktp.py` (29 проверок) |
| **ПЕРЕЧЕНЬ МАТЕРИАЛОВ** | Перечень материалов для подготовки студентов к промежуточной аттестации | `Перечни/01_Готовые/перечень МДК 02.01 КИП-31.docx` | [`ПЕРЕЧЕНЬ_INSTRUCTIONS.md`](ПЕРЕЧЕНЬ_INSTRUCTIONS.md), [`ЭТАЛОН_SPEC.md`](ЭТАЛОН_SPEC.md) | `scripts/generate_perechen_docx.py`, `scripts/validate_perechen.py` (21 проверка) |

**Учебное заведение:** ГБПОУ РО «Сальский индустриальный техникум» (СИТ).
**Специальность:** 15.02.07 «Автоматизация технологических процессов и производств (по отраслям)».

## 🔄 Поток данных (Workflow)

Процесс создания и проверки документов строго регламентирован:

1. **Источник**: Методист помещает актуальную Рабочую Программу (РП) в папку `RP/01_Актуальные/`. Скрипты и ИИ читают РП **только отсюда** — никогда из `02_Оригиналы/` или `03_Архив/`.
2. **Парсинг**: Скрипт (`extract_rp_data.py`, `build_ktp_json.py` или специализированный `build_data_02_01_kip31.py` / `build_json_03_02.py`) извлекает данные из РП и формирует структурированный `.json` файл в `scripts/`.
3. **Генерация**: Скрипт `generate_ktp_docx.py` берёт `.json` и эталон, создавая итоговый `.docx` файл в папке `KTP/`.
4. **Валидация**: Скрипт `validate_ktp.py` (29 проверок: часы, темы, нумерация, литература, стиль) сверяет сгенерированный КТП с эталоном.
5. **Сверка**: При необходимости — `verify_ktp_vs_rp.py` или `check_0201_0202_vs_rp.py` — финальное сравнение Т2 КТП vs раздела 3.2 РП построчно.
6. **Результат**: Финальные отчёты сверки сохраняются в папке `Сверки/`. Копия готового КТП — в `/home/z/my-project/download/` (для скачивания преподавателем).

## 🚀 Быстрый старт

### Установка

1. Клонируйте репозиторий и создайте виртуальное окружение:
   ```bash
   git clone https://github.com/DimaNikolaevi4/YMK.git
   cd YMK
   python3 -m venv venv
   source venv/bin/activate  # Для Windows: venv\Scripts\activate
   ```
2. Установите зависимости (необходимы для парсинга `.docx` и работы с таблицами):
   ```bash
   pip install python-docx openpyxl lxml
   ```
3. **Важно**: Перед запуском любых скриптов генерации убедитесь, что исходная Рабочая Программа находится в папке `RP/01_Актуальные/`, а не в корне или в архиве.

### Сценарий А — создание КТП «с нуля» по РП

```bash
# 1. Положить РП в RP/01_Актуальные/
# 2. Извлечь данные в JSON (выбрать подходящий сборщик)
python3 scripts/extract_rp_data.py RP/01_Актуальные/15.01.37_РП_ПМ.02_2025.docx

# 3. Собрать data-JSON для генератора (на основе извлечённых данных)
python3 scripts/build_ktp_json.py   # или специализированный build_data_02_01_kip31.py / build_json_03_02.py

# 4. Сгенерировать КТП
python3 scripts/generate_ktp_docx.py \
    --data scripts/data_05_02_example.json \
    --output "KTP/КТП МДК 05.02 М 2 курс.docx"

# 5. Валидировать (обязательно!)
python3 scripts/validate_ktp.py \
    --doc "KTP/КТП МДК 05.02 М 2 курс.docx" \
    --data scripts/data_05_02_example.json

# 6. Финальная сверка Т2 КТП vs РП 3.2 (построчно)
python3 scripts/verify_ktp_vs_rp.py
```

Ожидаемый результат: `ИТОГО: 29 проверок, провалено: 0`.

### Сценарий Б — синхронизация существующего КТП с новым РП

```bash
# 1. Проверить расхождения текущего КТП с новым РП
python3 scripts/check_0201_0202_vs_rp.py

# 2. Синхронизировать data-JSON с .docx (col.8/col.9)
python3 scripts/sync_data_json_col8_col9.py

# 3. Перегенерировать КТП и валидировать
python3 scripts/generate_ktp_docx.py --data data.json --output KTP/...
python3 scripts/validate_ktp.py --doc KTP/... --data data.json

# 4. Если расхождение с УП — вопрос владельцу, решение зафиксировать в worklog.md
```

Полный сценарий описан в [`KTP_INSTRUCTIONS.md`](KTP_INSTRUCTIONS.md) §14.1 (сценарий А) и §14.2 (сценарий Б).

## 📋 Направление 1 — КТП (календарно-тематический план)

### Единственный эталон

**`KTP/КТП МДК 05.02 М 2 курс.docx`** — золотой стандарт оформления. Любой сгенерированный КТП должен быть структурно идентичен ему:

- **Титульный лист:** `МИНИСТЕРСТВО ОБРАЗОВАНИЯ РОСТОВСКОЙ ОБЛАСТИ` (без «общего и профессионального» — это зафиксировано в `logic.md` §4 и проверяется валидатором проверкой 6b)
- **7 таблиц**: УТВЕРЖДАЮ (без рамки), Таблица 1, Таблица 2, 2а, 2б, 2в, 2г
- **Таблица 1** — распределение часов: 12 колонок, 4-строчная шапка с объединениями (`gridSpan`), 12 строк. Высоты: шапка 219/234/1758/237 tw, данные 215 tw.
- **Таблица 2** — содержание обучения: **11 колонок** (включая ОК, ПК, ФИО преподавателя), шапка 3 строки + номерная. Высоты: шапка 20/230/1695 tw, тело 20 tw.
- **Таблица 2г (ЭИ)** — электронные источники с 5-й колонкой `URL (ссылка)`
- **Без заливки ячеек** (все ячейки белые/auto — проверка 11а)
- **Times New Roman**: титул 12pt (style `Заголовок1`, EMU 152400), таблицы 10pt, литература 9pt
- **4 разрыва страницы** — между титулом и Т1, Т1 и Т2, Т2 и Т2а, Т2а и Т2б
- **Строка аттестации** в Т2: номер, название, 2 часа — графы 5-10 (ОК/ПК/вид/мат/задания/контроль) пустые (проверка 9)
- Слово «час» в титуле склоняется автоматически (8→«часов», 2→«часа», 60→«часов») — проверка 7е

### Как сгенерировать КТП (для ИИ-ассистента)

Подробно — в [`KTP_INSTRUCTIONS.md`](KTP_INSTRUCTIONS.md) §2 (извлечение из РП) и §14.1 (сценарий А, 10 шагов). Кратко:

1. **Прочитать инструкции:** [`создание_КТП.md`](создание_КТП.md) (индекс), [`KTP_INSTRUCTIONS.md`](KTP_INSTRUCTIONS.md) (сценарий), [`logic.md`](logic.md) (правила).
2. **Изучить эталон:** `KTP/КТП МДК 05.02 М 2 курс.docx` — структура, шрифты, тексты шапок.
3. **Извлечь данные из РП** (`RP/01_Актуальные/`): темы, часы, занятия, литература, оснащение.
4. **Подготовить JSON** в формате `scripts/data_05_02_example.json`. Ключевые поля часов (источник — строка «МДК …» тематического плана РП, раздел 3):
   - `total_hours` — кол. 3 строки МДК (для МДК 05.02: 112);
   - `practice_hours` — кол. 4 строки МДК («в форме практической подготовки»);
   - `practical_prep_hours` — то же, что `practice_hours`, но явно (важно для МДК с учебной практикой — см. `logic.md` §6.2);
   - НЕ путать: 96 = 60 + 36 уч. практики — по разделу целиком (РП, табл. 3.1); практика планируется отдельно и на титул КТП не попадает.
5. **Сгенерировать:**
   ```bash
   python3 scripts/generate_ktp_docx.py --data data.json --output "KTP/КТП МДК 05.02 М3 курс.docx"
   ```
6. **Провалидировать (обязательно):**
   ```bash
   python3 scripts/validate_ktp.py --doc "KTP/КТП МДК 05.02 М3 курс.docx" --data data.json
   ```
   Ожидается: 29/29 проверок пройдено.
7. **Сохранить** с именем `КТП МДК [код МДК] М[номер курса] курс.docx` в `KTP/`.

## 📋 Направление 2 — ПЕРЕЧЕНЬ МАТЕРИАЛОВ

### Что это за документ

«Перечень материалов для подготовки студентов к промежуточной аттестации» — обязательный методический документ СИТ, оформляется на каждый МДК отдельно. Содержит:

1. **Титульный блок** — шапка Министерства, УТВЕРЖДАЮ, заголовок «ПЕРЕЧЕНЬ МАТЕРИАЛОВ», учебный год, МДК, специальность, группа, преподаватель, согласование с ЦК.
2. **Контроль знаний** — таблица: форма контроля (диф. зачёт / защита курсового проекта / экзамен квалификационный), раздел, сроки по урокам.
3. **Требования к результатам освоения** — структурированный блок «иметь практический опыт / уметь (обязательная часть) / уметь (вариативная часть) / знать (обязательная) / знать (вариативная)».
4. **Перечень самостоятельных, практических и лабораторных работ** — большая таблица с разделами МДК, темами, практическими работами, лабораторными и самостоятельными работами.
5. **Вопросы к дифференцированному зачёту** (или курсовое проектирование).
6. **Критерии оценки знаний студентов** (5/4/3/2).
7. **Лист ознакомления студентов** — таблица ФИО / Дата / Подпись по каждой группе.

### Образцы

В папке [`Перечни/02_Архивные/`](Перечни/02_Архивные/) лежат 4 эталонных образца, охватывающих разные варианты документа. Каждый файл хранится в двух форматах: `.doc` (оригинал) и `.docx` (сконвертирован для парсинга через `python-docx`).

| Файл | МДК | Особенности |

### Как сгенерировать ПЕРЕЧЕНЬ (для ИИ-ассистента)

1. **Прочитать методику:** [`ПЕРЕЧЕНЬ_INSTRUCTIONS.md`](ПЕРЕЧЕНЬ_INSTRUCTIONS.md) — покомпонентный разбор документа и алгоритм сборки.
2. **Изучить спецификацию эталона:** [`ЭТАЛОН_SPEC.md`](ЭТАЛОН_SPEC.md) — анализ 4 образцов, выявленные отклонения, спецификация «сводного эталона».
3. **Изучить образцы** в папке `Перечни/02_Архивные/` — выбрать ближайший по структуре (с курсовым проектом / без, 1 группа / 2 группы).
4. **Извлечь данные из РП** (`RP/01_Актуальные/`): разделы, темы, перечень практических и самостоятельных работ, вопросы к зачёту, компетенции.
5. **Подготовить JSON** в формате (планируется `scripts/data_perechen_example.json`).
6. **Сгенерировать** (когда `scripts/generate_perechen_docx.py` будет готов):
   ```bash
   python scripts/generate_perechen_docx.py --data scripts/data_perechen_mdk0201_kip31.json \
     --out "Перечни/01_Готовые/перечень МДК XX.XX.docx" --blocks all
   ```
7. **Провалидировать** (когда `scripts/validate_perechen.py` будет готов).

> ✅ Генератор и валидатор перечней готовы; собранные документы — в `Перечни/01_Готовые/`, методика — [`ПЕРЕЧЕНЬ_INSTRUCTIONS.md`](ПЕРЕЧЕНЬ_INSTRUCTIONS.md).

## 📊 Главные скрипты — резюме (детально в [`scripts/README.md`](scripts/README.md))

### `generate_ktp_docx.py` (36K, 720 строк) — канонический генератор КТП

- **CLI:** `--data data.json --output "KTP/...docx"`
- **Зависимости:** `argparse`, `json`, `sys` (stdlib) + `python-docx`
- **Внутренних импортов:** нет (самодостаточный)
- **Хардкоды путей:** НЕТ (полностью параметризован через CLI)
- **Эталон:** `KTP/КТП МДК 05.02 М 2 курс.docx` — не открывает напрямую, воспроизводит структуру в коде (twips, EMU)
- **Структура:** 7 таблиц, 4 page break, TNR 12pt (титул, стиль `Заголовок1`)/10pt (таблицы)/9pt (литература), без заливок
- **Контрольные суммы:** при запуске печатает warning если `theory + practice + attestation ≠ total`
- **Риски:** см. [`scripts/README.md`](scripts/README.md) и worklog.md (запись `script-deep-analysis`)

### `validate_ktp.py` (20K, 340 строк) — валидатор, 29 проверок

- **CLI:** `--doc ...docx --data data.json --year 2026`
- **Зависимости:** `argparse`, `json`, `re`, `sys`, `zipfile`, `collections.Counter` + `python-docx`
- **Хардкоды путей:** НЕТ
- **29 проверок** по категориям: ZIP-валидность, структура (7 таблиц, 12/11/5 колонок), шапка Т2 (13 эталонных текстов), часы (5 проверок: Σ занятий = total, теория+практика+аттестация, объём программы в титуле, «в т.ч. в форме практ. подготовки», склонение «час»), темы (построчная сверка), нумерация, аттестация, литература (свежесть 5 лет + URL), стиль (без заливок + TNR), Т1 КДЗ, Т1 суммы (4 проверки), Т1/Т2 стили (высоты строк)
- **Критерий прохождения:** 29/29 (генератор) / 28/29 (эталонные оригиналы — провал в проверке 7е из-за опечатки «60 (часа)» вместо «часов»)
- **Известные штатные провалы:** проверка 7е — эталонная опечатка владельца, генератор её исправляет, валидатор ловит как сигнал «файл не от нашего генератора»

### `generate_ktp_05_02.py` (65K, 920 строк) — устаревший прототип

⚠️ **Кандидат на перенос в `scripts/_archive/`** — устарел, не соответствует эталону, нарушает ≥6 проверок валидатора (заливки `D9E2F3`/`F2F2F2`, нет Т2г/ЭИ, нет высот строк, 6 таблиц вместо 7, «ОБЩЕГО И ПРОФЕССИОНАЛЬНОГО» vs без него, размеры 7-8pt вместо 10pt).

- **CLI:** НЕТ (запускается без аргументов, данные захардкожены в коде)
- **Данные в коде:** `MDK_DATA` (25 строк), `TOPICS` (280 строк, 8 тем × 56 занятий), `EQUIPMENT` (10), `SOURCES_BASIC`+`SOURCES_ADDITIONAL` (30)
- **Хардкоды путей:** 1 (`output = '/home/z/my-project/YMK/KTP/КТП МДК 05.02 М 2 курс.docx'`)
- **Почему 65K:** ~500 строк данных как Python-литералы (vs `generate_ktp_docx.py` 36K — данные в JSON, не в коде)
- **Эталон:** docstring ссылается на `КТП МДК 02.01` (НЕ на канонический `05.02`) — морально устарел
- **Связанные скрипты-патчеры** (тоже кандидаты в `_archive/`): `rename_books.py`, `update_pages.py`, `_archive/fix_book_vars.py` — все патчат исходник `generate_ktp_05_02.py`, что бессмысленно после перехода на JSON-driven генератор
