# ПРАКТИЧЕСКИЕ_INSTRUCTIONS.md — методика разработки практических работ

**Роль файла:** 🤖 СЦЕНАРИЙ + методика третьего направления репозитория («ПРАКТИЧЕСКИЕ РАБОТЫ»). Адресован ИИ-агенту и владельцу. Создание документа — по шагам, стресс-тест эталона — после правок владельца.

**Статус:** принято решение владельца (2026-11-02):
- формат итоговых документов — **только .docx** (генерация через `scripts/generate_practical_docx.py`);
- первая партия — **только КТП МДК 02.01 С-21-22, 2 курс** (7 работ, 12 часов);
- раздел «Оборудование» — **один абзац одной строкой** (письменные принадлежности, листы А4; для компьютерных работ — «ПК с ПО …»);
- заголовок документа — **«Практическая работа № N»** (пример стиля — файл `E:\Бардаков ПР МДК 03.02 3 КУРС.doc` владельца, работа № 1, про OpenProj);
- контрольные вопросы и литература — **в конце** документа (вопросы = вопросы для защиты, форма контроля КТП — «Защита пр.раб.»).

## 1. Источники данных (строго, по приоритету)

| Данные | Источник | Примечание |
|---|---|---|
| Тема работы | КТП, Таблица 2, колонка 2, строки «Практическое занятие № N …» | Точное переписывание формулировки, без пересказа |
| Количество часов | КТП, Таблица 2, колонка 3 той же строки | В КТП МДК 02.01: ПЗ 1–2 по 1 ч, ПЗ 3–7 по 2 ч |
| Форма контроля | КТП, колонка 10 («Защита пр.раб.») | В методику не выносится, определяет роль контрольных вопросов |
| Содержание практического | РП (`RP/01_Актуальные/15.01.37_РП_ПМ.02_2025.docx`), раздел 3.2, «Практические занятия» | Контекст тем теории |
| Литература | КТП, Таблицы 2б (ОИ), 2в (ДИ), 2г (ЭИ) | Только с индексами ОИ/ДИ/ЭИ + нормативные ГОСТ, упомянутые в Т2 КТП |
| Профессия, МДК, группы, курс, семестр | Титул КТП | |
| Теория для специфических ПО | Учебные материалы владельца (как в примере OpenProj) | Запрашивать у владельца, если источника нет в репо |

> ⚠️ **Ловушка нумерации:** в КТП МДК 03.02 номера занятий дублируются (два «Практическое занятие № 1», два «№ 2»). Если номера повторяются — вопрос владельцу, решение фиксировать в `worklog.md`. В КТП МДК 02.01 нумерация чистая (1–7).

> ⚠️ **Ловушка РП vs КТП:** формулировки тем в РП 3.2 и Т2 КТП совпадают дословно, но в РП вместо «№» пишется «Практическое занятие. Составление …» (точка вместо номера). Брать тему из **КТП**.

## 2. Структура документа (фиксированная, 8 блоков)

```text
1. Шапка (без титульного листа):
   ПРАКТИЧЕСКАЯ РАБОТА № <N>                                  (14 pt, по центру, полужирный)
   <наименование МДК>                                         (12 pt, по центру)
   ПМ <код> <наименование ПМ>                                 (12 pt, по центру)
   Профессия <код> <наименование>                             (12 pt, по центру)
   Группы <группы> · <курс> курс · <семестр> семестр          (12 pt, по центру)
   Количество часов: <N>                                      (12 pt, по центру, полужирный)

2. Тема: «…»                 — точная формулировка из колонки 2 Т2 КТП
3. Цель работы:              — глаголы совершенного вида («составить», «научиться»)
4. Оборудование:             — ОДНА строка: «Тетрадь, письменные принадлежности,
                               листы А4.» (+ «ПК с ПО …» для компьютерных работ)
5. Краткая теория:           — 2–4 абзаца, строго прикладные: только те понятия,
                               формы и реквизиты, которые реально используются
                               в «Ходе работы». Без энциклопедической фактологии.
6. Ход работы:               — 5–10 нумерованных шагов:
                               а) ознакомление с формой/источником →
                               б) заполнение реквизитов (каких именно — перечислить) →
                               в) оформление сводного документа →
                               г) вывод.
                               Запрещены шаги-«пустышки» («ознакомьтесь с теорией»).
7. Содержание отчета:        — что студент сдает преподавателю (заполненные формы,
                               таблицы, вывод); связь с формой контроля «Защита пр.раб.»
8. Контрольные вопросы:      — 3–5 вопросов по теории и ходу работы, для защиты
9. Литература:               — источники из Т2б/2в/2г КТП с индексами (ОИ1, ДИ1, ЭИ1…)
                               + ГОСТ из Т2 КТП; формат по образцу КТП
```

Блоки 2–7 — до отчета, блоки 8–9 — в конце (решение владельца).

## 3. Правила оформления .docx

- Times New Roman, 12 pt (шапка-заголовок 14 pt полужирный, по центру);
- A4, поля: левое 3 см, правое 1,5 см, верхнее 2 см, нижнее 2 см;
- межстрочный интервал 1,15; абзацный отступ первой строки 1,25 см;
- заголовки блоков — полужирным, отдельной строкой, без нумерации;
- нумерованные пункты «Хода работы» — обычные абзацы с текстом «1. …», «2. …»;
- без заливок ячеек, без таблиц в шапке, без титульного листа и границ.

## 4. Именование файлов

```text
Практическая работа № <N> <код МДК> <группы>.docx
Пример: Практическая работа № 1 МДК 02.01 С-21-22.docx
Папка: Практические/01_Готовые/
```

## 5. Пайплайн (для ИИ-агента)

```bash

# 1. Определить перечень работ: строки «Практическое занятие» Т2 КТП (тема, часы)
# 2. Заполнить entries в scripts/data_practical_<код>_test.json (нейтральный префикс test, чтобы не перекрывать КТП-данные)
#    Формат scripts/data_practical_0201_s21.json: work{number;hours;topic;goal;equipment;
#    theory[];steps[];report[];questions[];literature[]}
# 3. Сгенерировать работу(ы):
python3 scripts/generate_practical_docx.py --data scripts/data_practical_0201_s21.json --work 1
# 4. Визуальный контроль владельца (шрифт, стили, смысл) — docx открыть в Word
# 5. Правки владельца → закрепить изменения в JSON ЭТАЛОНА (work 1) и в §2–3 этой методики
# 6. Остальные работы: заполнить content в data-JSON и повторить шаг 3
# 7. Зафиксировать решение владельца в worklog.md
```
